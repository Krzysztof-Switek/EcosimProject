## 1. Cel sesji

Przebudowa logiki nawigacji aplikacji na **prowadzony, sekwencyjny workflow** oparty o nowy,
dwupoziomowy wymiar tożsamości danych: **Model (Ecopath) → Scenariusz (Ecosim)**, którego wcześniej
w ogóle nie było (był płaski `scenario`). Docelowa sekwencja wyboru:

1. **Models** — wybór modeli z katalogu output (rozpoznawane po `<HEADER ecopath/>` → `ModelName`).
2. **Scenarios** — scenariusze spośród wybranych modeli (`<HEADER ecosim/>` → `EcosimScenario`).
3. **Time step** — dane roczne (annual) czy miesięczne (monthly).
4. **Variables** — lista zmiennych pogrupowana jak dotąd (kategorie Results Extractor).
5. (przy zmiennej) **Models & scenarios** — dostrojenie, które serie model+scenariusz narysować.

Zasada nadrzędna ustalona w trakcie: **nic nie jest zaznaczone domyślnie na żadnym etapie** —
użytkownik wybiera po kolei; jeśli coś nie zostało wybrane wcześniej, **nie pojawia się** dalej.
Wykresy **tylko wizualizują** wybrane dane — nic nie jest liczone.

## 2. Nowy wymiar danych: Model → Scenariusz

Nagłówki CSV niosą dwa autorytatywne pola:
- `<HEADER ecopath/>` → **`ModelName`** (model Ecopath), np. „Baltic Sea_new", „HAS_Cumulative".
- `<HEADER ecosim/>` → **`EcosimScenario`** (scenariusz Ecosim).

Jeden model Ecopath może mieć **≥1 scenariusz** Ecosim. Po ingestii wykryto **2 modele**:
- **Baltic Sea_new** → scenariusze `baltic_ecosim`, `baseline_cumulative`,
- **HAS_Cumulative** → scenariusz `has_cumulative`.

Drivery wejściowe (BAU/HAS, `domain=input`) nie mają modelu Ecopath → `model=NULL` (osobna sekcja
„Drivers (inputs)", niezależna od kroków 1–2).

**Decyzja techniczna:** slug scenariusza jest globalnie unikalny i jednoznacznie wskazuje model,
więc partycjonowanie Parquet **bez zmian** (`scenario=/domain=/variable=/freq=`) — `model`/`model_name`
to zwykłe kolumny w tidy, nie partycje (brak repartycji, brak przenoszenia plików).

## 3. Backend (Python, FastAPI) — zmiany

- **Schemat tidy** (`core/schema.py`): dodane kolumny `model`, `model_name` (przed `scenario`),
  zarówno w `TIMESERIES_COLUMNS` jak i `TIMESERIES_ARROW_SCHEMA`.
- **Parser** (`ingestion/parsers/ecosim_csv.py`): `parse_ecosim_csv(..., model=, model_name=)`;
  fallback — gdy nie podano, bierze `ModelName` z nagłówka i slugifikuje.
- **Pipeline** (`ingestion/pipeline.py`): `_discover_output` zwraca `OutputRun`
  (model_id, model_label, scenario_id, scenario_label, ecosim_dir); rejestr modeli;
  eksport `dictionaries/models.csv` i rozszerzony `scenarios.csv` (kolumny `model`, `model_name`).
- **Store** (`ingestion/store.py`): koercja nowych kolumn do `string`.
- **Katalog DuckDB** (`catalog/build.py`): `catalog_datasets` niesie `model`/`model_name`
  (`any_value`), nowa tabela `dim_models`.
- **Serwis** (`catalog/service.py`):
  - `list_models()` — modele z ich scenariuszami (tylko output, `model IS NOT NULL`),
  - tree z polami `model`/`model_name` na każdym węźle scenariusza,
  - `query_timeseries` z filtrem `model` oraz **`month_from`/`month_to`** (1–12, miesiąc-w-roku);
    zwraca też `model`, `model_name`.
- **API** (`api/routers/`): `GET /catalog/models`; w `/timeseries` parametry `model`,
  `month_from`, `month_to`. `/admin/reload` zwraca też listę modeli.
- **Testy parsera**: 7/7 OK (sygnatura `parse_ecosim_csv(scenario=...)` zachowana, `model` domyślnie `None`).

**Re-ingestia:** 668 plików → **7,8 mln wierszy, 146 datasetów, 2 modele, 5 scenariuszy** — bez błędów.

## 4. Frontend (React + Vite + TS) — zmiany

### 4.1 Lewy panel — prowadzony stepper (`features/catalog/Sidebar.tsx`)
Zastąpił dawny `CatalogPanel.tsx`. Cztery kroki w jednej kolumnie:
- **1. Models** — checkboxy modeli (rozwijalna sekcja).
- **2. Scenarios** — scenariusze **tylko z wybranych modeli**, grupowane pod modelem, z „all/none";
  dopóki nie wybrano modelu → „select a model first".
- **3. Time step** — segmented control Annual / Monthly (nazwa „Time step", nie „Frequency").
- **4. Variables** — akordeon kategorii + filtr; klik w nazwę/zmienną ustawia ją jako **aktywną**.

### 4.2 „Krok 5" — dokowany picker przy zmiennej (`features/catalog/VariableSeriesPicker.tsx`)
- Na **górze drugiej kolumny**, widoczny stale (nie pływające okienko — wcześniejszy popover usunięto).
- Pokazuje **wyłącznie modele i scenariusze wybrane w krokach 1–2** (model nieodznaczony wcześniej
  nie może się tu pojawić); drivery (bez kroku Model) traktowane niezależnie.
- **Progresywne rozwijanie „w dół"**: najpierw modele; scenariusze pojawiają się dopiero po
  rozwinięciu modelu (chevron) — nie wszystkie naraz. „select all / clear" per model.
- Domyślnie **nic nie zaznaczone**; użytkownik wybiera serie do narysowania. Przycisk „Clear".

### 4.3 Workspace analizy (`features/timeseries/AnalysisView.tsx`)
- Usunięty globalny selektor scenariuszy; serie pochodzą **per zmienna** z pickera (krok 5).
- Kontrolki wspólne: **Groups**, **Fleets** (startują puste), oraz zakres zależny od time stepu:
  - **Annual** → „Year range" (pola lat),
  - **Monthly** → „Month range" — **dwa `<select>` z angielskimi nazwami miesięcy**
    (January…December, 1–12), bez roku (zrezygnacja z natywnego `<input type="month">`,
    który dokładał mylący rok i lokalizował nazwy).
- Chipy w „koszyku" (manifest dla R) przełączają aktywną zmienną; manifest niesie per-zmienna serie.

### 4.4 Stan w `App.tsx`
- `selectedModels`, `selectedScenarios`, `freq`, `selectedIds`, `focusedVarId`, `perVarScenarios`.
- **Start i po „Reload Data": wszystko puste** (reset).
- `toggleModel` — włączenie modelu **tylko udostępnia** jego scenariusze w kroku 2 (nie zaznacza ich);
  wyłączenie usuwa jego scenariusze z puli.
- `availableScenarios(v)` — kandydaci dozwoleni przez kroki 1–2 (drivery zawsze dostępne).
- `effectiveScenarios(v)` — narysowane serie = override użytkownika ∩ dostępne; **domyślnie puste**.
- `focusedVariable` — z fallbackiem do pierwszej wybranej (picker zawsze widoczny, gdy coś wybrano).

## 6. Środowisko / uruchamianie (bez zmian względem 09.06)

```powershell
# backend (z katalogu projektu)
$env:PYTHONPATH="backend"; .\.venv\Scripts\python.exe -m ecosim.cli serve --port 8000
# frontend
cd frontend; $env:NODE_OPTIONS="--use-system-ca"; npm run dev   # http://localhost:5173
```
Po zmianach w `service.py`/routerach backend wymaga restartu; po zmianie schematu/parsera —
ponowna ingestia (`python -m ecosim.cli ingest`). Maszyna za firmowym CA: `uv pip install --native-tls`,
Node `--use-system-ca` (szczegóły w pamięci projektu).

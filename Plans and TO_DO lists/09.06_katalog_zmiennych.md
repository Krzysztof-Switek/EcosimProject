# Katalog zmiennych — stan i kierunek rozwoju

**Data:** 2026-06-09
**Zakres:** lewy panel aplikacji („Variable catalog") — indeks zmiennych modelu, po którym
użytkownik nawiguje, zanim zbuduje porównanie/analizę. Dokument opisuje szczegółowo co już
zrobiliśmy oraz **nowy podział hierarchii**, który teraz wprowadzamy.

> Konwencja: **wszystkie napisy UI po angielsku** (reguła projektu). Ta dokumentacja —
> dla zespołu — po polsku.

---

## 1. Cel katalogu

Katalog to **indeks nawigacyjny** nad kanonicznym store (Parquet + DuckDB). Pokazuje, jakie
zmienne są dostępne i w jakich wymiarach, tak aby użytkownik mógł szybko znaleźć interesującą
go wielkość, zanim zbuduje wykres porównawczy. Katalog jest **produktem ingestii**
(regenerowalny), nie jest pisany ręcznie.

---

## 2. Jakie zmienne mamy (wymiarowość)

Po ingestii (`python -m ecosim.cli ingest`): **5 scenariuszy** (`baltic_ecosim`,
`baseline_cumulative`, `has_cumulative` — output; `bau`, `has` — input/drivery),
lata 1998–2050, częstotliwości **annual** i **monthly**, **50 grup funkcyjnych**, **9 flot**.

Wymiarowość każdej zmiennej output (z katalogu) determinuje jej kategorię:

| zmienna | groups | fleets | partner | znaczenie |
|---|---|---|---|---|
| biomass, catch, mortality, consumption_biomass, feedingtime, tl, value, weight | 50 | 0 | 0 | per grupa funkcyjna |
| catch_fleet_group, mort_fleet_group, landings, value_fleet_group, discardmortality…, discardsurvival… | 50 | 9 | 0 | flota × grupa |
| **predation** | 44 | 0 | 45 | śmiertelność predacyjna ofiary wg drapieżników |
| **prey** | 45 | 0 | 44 | dieta/konsumpcja drapieżnika wg ofiar |
| fib, kemptonsq, shannondiversity, tlc, totalcatch | 0 | 0 | 0 | wskaźnik globalny (jedna seria) |
| (drivery: bottom_o2, pb, salinity_*, temp_10m_summer, codrv_4ml, saturation_*) | 0 | 0 | 0 | input — trend driverów |

## 3. 7 kategorii „Results Extractor" + mapowanie

Wzorujemy się na ekstraktorze EwE (7 grup zmiennych output). Część kategorii nie ma u nas
danych — są **ukrywane** w panelu.

| Kategoria (id / etykieta EN) | Nasze zmienne |
|---|---|
| `functional_groups` / **Functional groups** | biomass, catch, mortality, consumption_biomass, feedingtime, tl, value, weight |
| `predators_with_prey` / **Predators (with prey)** | prey |
| `prey_with_predators` / **Prey (with predators)** | predation |
| `fleets_only` / **Fleets** | *(brak danych — ukryte)* |
| `fleets_with_prey` / **Fleets (with prey)** | catch_fleet_group, mort_fleet_group, landings, value_fleet_group, discardmortalityfleetgroup, discardsurvivalfleetgroup |
| `fitting_stats` / **Fitting statistics** | *(brak danych — ukryte)* |
| `indicators` / **Indicators** | fib, kemptonsq, shannondiversity, tlc, totalcatch |

Drivery (`domain=input`) trafiają do osobnej sekcji **Drivers (inputs)**.

## 4. Co już zrobiliśmy (szczegółowo)

### 4.1 Parser — konsolidacja zmiennych relacyjnych
`backend/ecosim/ingestion/parsers/ecosim_csv.py`, `_variable_and_target`:
- pliki `predation_<prey>` → jedna zmienna `predation` (group=ofiara, partner=drapieżnik),
- pliki `prey_<predator>` → jedna zmienna `prey` (group=drapieżnik, partner=ofiara).

Dzięki temu zamiast 45 osobnych pozycji `prey_*` mamy **jedną** zmienną `prey`,
symetryczną do `predation`. Efekt: katalog skurczył się z **410 → 146 datasetów**
(te same 7,8 mln wierszy). Naprawiło to też wcześniejszą utratę informacji (drapieżnik
z nazwy pliku nie był wcześniej zapisywany).

### 4.2 Kanoniczny schemat tidy
Wszystkie kształty CSV sprowadzone do jednej tabeli (`scenario, domain, variable, freq,
date, year, month, group_id, group_name, fleet_id, fleet_name, partner_id, partner_name,
value, unit`). Szczegóły: `docs/data-contract.md`.

### 4.3 Klasyfikacja do kategorii — jedno źródło prawdy
`backend/ecosim/catalog/categories.py`: kanoniczna kolejność kategorii + reguła
(samonaprawiająca się dla nowych zmiennych): `predation`/`prey` po nazwie, reszta z
wymiarów (`n_fleets>0` → fleety; `n_partners>0` → predators; `n_groups>0` → functional;
inaczej → indicators). Reguła zapisana raz, jako współdzielony snippet SQL `CATEGORY_SQL`.

### 4.4 Katalog DuckDB
`backend/ecosim/catalog/build.py`: tabela `catalog_datasets` (jeden wpis na
scenario×domain×variable×freq) z policzonymi `n_groups/n_fleets/n_partners`, zakresem lat,
liczbą wierszy i **kolumną `category`** (dla output; dla input `NULL`). Widok `timeseries`
nad Parquet + tabele wymiarów (`dim_groups`, `dim_fleets`, `dim_scenarios`).

### 4.5 API
`backend/ecosim/catalog/service.py` + routery: `/catalog/scenarios`, `/catalog/tree`
(zawiera `category`), `/catalog/datasets`, `/dictionaries/groups|fleets`,
`/timeseries?variable=&freq=&scenario=&group=&fleet=&year_from=&year_to=`.

### 4.6 Frontend — panel katalogu
`frontend/src/features/catalog/`:
- `categories.ts` — angielskie etykiety + kolejność sekcji,
- `catalogIndex.ts` — spłaszcza drzewo per-scenariusz w globalną listę zmiennych
  (śledzi, które scenariusze mają daną zmienną; niesie `category`),
- `CatalogPanel.tsx` — renderuje **sekcje wg kategorii** w kanonicznej kolejności,
  **puste ukrywa**, drivery w osobnej sekcji; filtr tekstowy w obrębie sekcji.

Stan UI: napisy po angielsku; częstotliwość pokazywana jako badge (`yr`/`mo`) na każdej
pozycji; klik w zmienną otwiera moduł porównań po prawej.

## 5. Nowy podział hierarchii (wprowadzany teraz)

Cel: czytelniejsza nawigacja. Dwa usprawnienia.

### 5.1 Poziom 0 — pierwszy podział: Rok / Miesiąc (freq)
Najwyższy poziom katalogu to wybór częstotliwości: **Annual** / **Monthly**. Obecnie
`annual` i `monthly` to osobne pozycje rozróżniane tylko badge'em — chcemy, by to był
pierwszy, wyraźny podział. Zmienna pokazywana raz w obrębie wybranej częstotliwości
(badge `yr`/`mo` przy pozycji staje się zbędny).

Realizacja: przełącznik **Annual / Monthly** u góry panelu (segmented control). Filtruje
listę po `freq`; reszta hierarchii (kategorie → zmienne) pokazuje tylko wybraną częstotliwość.

### 5.2 Poziom 1 — kategorie jako rozwijane sekcje (accordion)
Sekcje kategorii (Functional groups, Predators (with prey), …) stają się **rozwijane**
(collapsible). Można mieć **kilka otwartych jednocześnie**. Nagłówek pokazuje liczbę
zmiennych; klik zwija/rozwija. Domyślnie otwarta pierwsza niepusta (Functional groups).

### 5.3 Poziom 2 — zmienne
Wewnątrz rozwiniętej kategorii lista zmiennych (jak teraz: etykieta + liczba scenariuszy),
klik wybiera zmienną do modułu porównań.

### Docelowa hierarchia panelu
```
Variable catalog                     [ filter… ]
┌─ ( Annual | Monthly )  ← poziom 0: przełącznik freq
│
├─ ▸ Functional groups        (8)    ← poziom 1: rozwijana sekcja kategorii
├─ ▾ Predators (with prey)    (1)
│     • Prey of predator (diet)            ← poziom 2: zmienne
├─ ▾ Prey (with predators)    (1)
│     • Predation mortality
├─ ▸ Fleets (with prey)       (6)
├─ ▸ Indicators               (5)
└─ ▸ Drivers (inputs)         (10)
```

### 5.4 Multi-wybór grup (decyzja: OBA)
Wprowadzamy **oba** usprawnienia:
- (a) **sekcje kategorii** w katalogu jako rozwijane (accordion z kilkoma otwartymi) — opis 5.2,
- (b) selektor **50 grup funkcyjnych** w module porównań zamieniony z długiej listy checkboxów
  na **rozwijany dropdown z multi-wyborem** (zwinięty pokazuje „N selected", klik rozwija
  listę z wyszukiwarką). To samo dotyczy selektora flot.

### 5.5 Badge yr/mo (decyzja: USUNĄĆ)
Po wprowadzeniu poziomu 0 (Rok/Miesiąc) częstotliwość jest już wybrana globalnie, więc badge
`yr`/`mo` przy pozycjach jest redundantny i go **usuwamy**. Zostaje badge z liczbą scenariuszy.

### Uwaga implementacyjna

użytkownik zwija te, których nie potrzebuje — prościej i bez stanu „pierwsza otwarta".
